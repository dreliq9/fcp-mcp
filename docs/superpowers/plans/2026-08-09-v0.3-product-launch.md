# fcp-mcp v0.3 Product Launch Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish one coherent, verified `fcp-mcp==0.3.0` product across GitHub, PyPI, and the official MCP Registry, with a reproducible first run and truthful Final Cut Pro compatibility evidence.

**Architecture:** Keep draft PR #2's 94-tool MCP runtime intact. Add a packaged sample-export CLI, executable public documentation contracts, compatibility/support surfaces, isolated PyPI and Registry workflows, and real release-canary evidence. Build and publish only from the exact verified merge commit.

**Tech Stack:** Python 3.10–3.13, MCP Python SDK v2, pytest, Ruff, GitHub Actions, PyPA Trusted Publishing, official `mcp-publisher` v1.8.1, FCPXML 1.11, Final Cut Pro 12.2+, macOS 15.6+.

## Global Constraints

- Version is exactly `0.3.0`; profile counts are `inspect=30`, `workflow=34`, `edit=75`, `full=94`.
- Include draft PR #2's `youtube-mcp.materialized-clip-plan/v1` adapter.
- Add no MCP tools and no new live-control behavior.
- Default workflow remains inspect, prepare, review, hash approval, commit.
- Public copy promises bounded FCPXML interchange and tested FCP handoff, not complete autonomous FCP control.
- The visual proof must come from a real FCP import; reconstructed FCP UI is forbidden.
- PyPI and Registry jobs use separate short-lived OIDC credentials.
- Never move or reuse a published `v0.3.0` tag or PyPI version.
