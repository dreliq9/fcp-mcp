# fcp-mcp v0.3.0 Transactional Workflows Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use
> superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a deterministic, durable, approval-gated FCPXML workflow while
reducing the default MCP catalog and adding meaningful dual-channel results
without breaking existing success text.

**Architecture:** A static tool registry feeds a narrow MCP adapter and fixed
capability profiles. The SDK-independent workflow core executes a code-defined
inspect/plan/dry-run/validate/diff/approve/commit state machine backed by a
rollback-journal SQLite event ledger and private hashed artifacts.

**Tech Stack:** Python 3.10-3.13, Pydantic 2, MCP Python SDK, defusedxml,
lxml, SQLite, platformdirs, Hypothesis, pytest, Ruff.

**Platform prerequisite:** Complete
[`2026-07-27-macos-only-runtime.md`](2026-07-27-macos-only-runtime.md)
before resuming Task 15. It supersedes every Windows/Linux implementation or
test requirement in this plan.

## Global Constraints

- Work on `codex/v0.3-transactional-workflows`; do not push, tag, publish, or
  submit to a registry without separate authorization.
- macOS is the sole supported product runtime. Operational entry points reject
  non-Darwin before side effects; pure imports carry no portability promise.
- Keep `mcp>=1.27,<2` until Task 23's fresh SDK/specification research gate.
- Add `platformdirs>=4.11,<5` as a direct runtime dependency.
- Add `hypothesis>=6.161,<7` as a development-only dependency.
- Preserve all 89 existing tool names, accepted MCP inputs, coded failures, and
  exact successful text content in the `full` profile.
- The static profile counts after workflow integration are exactly:
  `inspect=30`, `workflow=34`, `edit=74`, and `full=93`.
- The no-argument default profile is `workflow`;
  `FCP_MCP_ENABLE_LIVE_CONTROL=1` remains an independent execution gate.
- Approval defaults to CLI mode. Client approval exists only when
  `FCP_MCP_WORKFLOW_APPROVAL=client`.
- Defaults are: approval TTL `86400`, maximum operations `100`, source bytes
  `134217728`, per-run artifact bytes `268435456`, and rendered diff bytes
  `204800`.
- Use SQLite rollback journaling, `synchronous=FULL`, foreign keys,
  `busy_timeout=5000`, and `BEGIN IMMEDIATE`. Do not enable WAL.
- Do not add a generic graph framework, MCP Tasks, OpenTelemetry, a background
  worker, or an LLM call inside the server.
- Prepare never changes the requested destination. Commit writes the exact
  approved candidate bytes and never replans silently.
- A status tool is read-only. Only commit and explicit CLI reconciliation may
  persist recovery decisions.
- Every filesystem claim is verified from bytes, hashes, parsing, or process
  state; process exit or prose alone is not evidence of success.
- Use `apply_patch` for hand-authored file edits and preserve unrelated user
  changes.

```python
# scripts/snapshot_tool_contracts.py
from __future__ import annotations

import asyncio
import json
from pathlib import Path

from fcp_mcp.server import mcp

OUTPUT = Path("tests/contracts/v0_2_1_catalog.json")


async def snapshot() -> dict[str, object]:
    tools = {}
    for tool in await mcp.list_tools():
        tools[tool.name] = {
            "input_schema": tool.inputSchema,
            "output_schema": tool.outputSchema,
            "annotations": tool.annotations.model_dump(
                by_alias=True, exclude_none=True
            ),
        }
    prompts = sorted(prompt.name for prompt in await mcp.list_prompts())
    return {"tools": dict(sorted(tools.items())), "prompts": prompts}


def main() -> None:
    OUTPUT.parent.mkdir(parents=True, exist_ok=True)
    OUTPUT.write_text(
        json.dumps(asyncio.run(snapshot()), indent=2, sort_keys=True) + "\n",
        encoding="utf-8",
    )


if __name__ == "__main__":
    main()
```
